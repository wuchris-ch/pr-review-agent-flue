AI code review that points to the exact line.

PR Review comments on a pull request only when it can cite the line that's wrong. For Python projects, a self-hosted platform can also prove the bug: it writes a test that fails on the PR, then suggests a fix that makes it pass.

How well it works

I tested it on Martian's public code review benchmark: 50 real pull requests from Sentry, Grafana, Keycloak, Discourse and Cal.com, with 173 issues that people had already confirmed. Before changing anything, I set 30 of those PRs aside and tuned only on the other 20. The chart shows the 30 held-out PRs, which none of the changes saw.

When PR Review leaves a comment, it's right 52% of the time, 7th best of 18 tools. Its weak spot is coverage. It finds 30% of the known issues, and the best tools find over 60%. Two changes raised recall from 25.5%: showing the model whole changed files instead of only the diff, and asking it to report concrete bugs anywhere in code the PR edits. A broader bug hunt doubled the false alarms, so I left it out.

For a fair comparison, I re-scored all 17 commercial tools with the same judge I used on mine. It agrees with the benchmark's own judge on 95.5% of 2,941 decisions. Every experiment and the full method are in the repo.

How a review works

The reviewer runs from your terminal, as a GitHub Action or as a GitHub App. For each pull request it:

  1. Reads the diff along with the code around it, like callers, tests and the README, all from the exact commit under review.
  2. Asks a model for findings. Security bugs, wrong behavior and broken project rules come before style.
  3. Checks each finding against the lines it cites, in a separate pass. If the code doesn't back it up, the finding is dropped.
  4. Posts what's left as one review with inline comments, tied to that commit.

The comment on the right is based on a real finding from a bug planted in the project's demo repo.

The discount is no longer applied. total() now charges tax on the full price and never uses discount. The README says to apply discounts before sales tax, and so does the docstring on line 5.

total(100, 0.2, 0.1) returned 88 before this change and returns 110 now. The only existing test uses a zero discount, so it still passes.

Proving the bug with a test

A comment that says "this looks wrong" still needs someone to check it. For regressions in small Python projects, the platform does that check itself. It runs on your own servers:

  1. Pins the base commit, the PR commit and the container image, so every step sees the same code.
  2. Writes a test for the suspected bug and runs it on both commits in a Docker container with no network and read-only source. It has to pass on the base and fail on the PR.
  3. Has a second agent check that the failure breaks documented behavior and isn't a change someone meant to make.
  4. Suggests a fix, which only counts if it passes the new test and the existing test suite.
  5. Waits for a person to approve or reject it, and records the decision against that exact commit.

Each review is a Temporal workflow backed by PostgreSQL, so it picks up where it left off if a worker crashes. The console on the left shows the pricing bug from above at the approval step.

To test the whole thing with a live model, I planted 9 multi-file bugs and added 9 harmless changes as controls. It reproduced all 9 bugs with failing tests, all 9 of its fixes passed hidden tests the agents never saw, and it flagged none of the harmless changes.

Try it

You need an API key for any OpenAI-compatible model. The CLI and the GitHub Action don't need a database or a hosted service.

Terminal
git clone https://github.com/wuchris-ch/pr-review-agent-flue.git
cd pr-review-agent-flue
npm ci && npm run build
cp .env.example .env  # model URL, key and name
npm run cli -- pr https://github.com/owner/repo/pull/123
.github/workflows/review.yml
- uses: wuchris-ch/pr-review-agent-flue@v0.3.0
  with:
    model-key: ${{ secrets.MODEL_GATEWAY_API_KEY }}
    model-url: ${{ secrets.MODEL_GATEWAY_BASE_URL }}
    model: ${{ secrets.REVIEW_AGENT_MODEL }}

The Action guide covers permissions and pull requests from forks. The platform quickstart starts the self-hosted version and the console with Docker Compose.

Built with

The reviewer is TypeScript on the Flue agent framework, tested with Vitest. The platform is Python, with FastAPI, Temporal, PostgreSQL and Docker, plus a React console. It's open source under the Apache-2.0 license.
